فهم خوارزمية ديكسترا من الصفر تماماً

دليل تعليمي يعتمد على القصص الواقعية، تفكيك كل المصطلحات المعقدة، والأنيميشن الحي خطوة بخطوة.

1. القصة الواقعية: ما هي المشكلة التي نحاول حلها؟

تخيل أنك سائق في تطبيق مثل Google Maps أو Uber، وتريد التحرك من منزلك في الحي (A) لتوصيل طلب إلى الحي (D).

مثال من واقعنا

أمامك طرق متعددة بين الأحياء:

  • طريق سريع ومباشر، لكن فيه زحام ويستغرق 11 دقيقة.
  • طريق يمر بحي وسيط هادئ، ويستغرق فقط 5 دقائق.

بدل أن تخمن بنفسك وتضيع وقتك في تجربة كل شوارع المدينة، نحتاج إلى عقل إلكتروني ذكي يجرب الطرق بأقل مجهود ويضمن لنا 100% أنه وجد أسرع مسار ممكن. هذا العقل الذكي هو بالضبط خوارزمية ديكسترا (Dijkstra).

2. تفكيك المصطلحات الغريبة (افهم المعنى بدون تعقيد)

في علوم الحاسوب، يستخدم المبرمجون كلمات إنجليزية قد تبدو مخيفة. دعنا نترجمها إلى لغة الحياة اليومية:

مصطلح 1: الرسم البياني الموزون (Weighted Graph)

ماذا يعني؟ هو ببساطة خريطة الشوارع!

  • العقدة (Node أو Vertex): هي الميدان، أو الحي، أو المدينة (مكان تقف فيه).
  • الحافة (Edge): هي الشارع أو الكوبري الذي يصل بين حيين.
  • الوزن (Weight): التكلفة! قد يكون عدد الكيلومترات، أو زمن الرحلة بالدقائق، أو حتى ثمن تذكرة المواصلات.
مصطلح 2: التهدئة أو تحسين المسار (Relaxation)

لماذا سميت Relaxation؟ تخيل أنك متوتر لأنك تظن أن مشوارك سيكلفك 100 جنيه. فجأة اقترح عليك صديقك طريقاً مختصراً سيكلفك 30 جنيهاً فقط! ماذا حدث لتوترك؟ انخفض وشعرت بـ (الاسترخاء أو الهدوء)!

في البرمجة، كلمة Relaxation تعني شيئاً واحداً فقط: "كلما وجدنا طريقاً أقصر لمدينة ما، نلغي الرقم القديم الغالي ونسجل الرقم الجديد الرخيص".

مصطلح 3: الخوارزمية الجشعة الطماعة (Greedy Algorithm)

هل هي صفة سيئة؟ لا، بل أسلوب تفكير! الإنسان الجشع يريد المكسب المضمون تحت يديه الآن ولا يحب المخاطرة بالمستقبل.

وديكسترا تفكر هكذا: في كل خطوة، تنظر حولها وتسأل: "من هي أقرب وأرخص مدينة متبقية أستطيع الوصول إليها حالياً؟ سأختارها فوراً وأعتبرها مضمونة نهائياً!".

مصطلح 4: المالانهاية (Infinity / ∞)

لماذا نضع مسافة كل المدن ∞ في البداية؟

لأنك في أول ثانية وأنت واقف عند بيتك، لا تعرف بعد كم دقيقة تفصلك عن باقي المدن البعيدة. فتعطيها افتراضياً رقم ضخم جداً لا يمكن تجاوزه (∞)، لتقول: "أي مسار حقيقي سأكتشفه لاحقاً -مهما كان طويلاً- سيكون حتماً أفضل من هذا المجهول الضخم".

4. الكود بلغة JavaScript (مع استرجاع المسار بالأسماء)

دعنا نترجم هذا التفكير المنطقي إلى أسطر برمجية واضحة جداً:

// 1. خريطة الشوارع والتكلفة بين الأحياء
const cityMap = {
    A: { B: 4, C: 2 },
    B: { A: 4, C: 6, D: 7 },
    C: { A: 2, B: 6, D: 3 },
    D: { B: 7, C: 3 }
};

function dijkstra(map, startCity) {
    const shortestTimes = {};   // أقل وقت للوصول لكل حي
    const cameFrom = {};        // الحي السابق (لمعرفة خط السير)
    const visited = new Set();   // الأحياء التي انتهينا من فحصها تماماً

    // تهيئة كل الأحياء بوقت مجهول ضخم (Infinity) ما عدا نقطة البداية
    for (let city in map) {
        shortestTimes[city] = Infinity;
        cameFrom[city] = null;
    }
    shortestTimes[startCity] = 0; // وقت البداية من بيتك هو صفر دقيقة

    while (visited.size < Object.keys(map).length) {
        // خطوة الطمع (Greedy): ابحث عن أقرب حي لم نزره بعد
        let current = null;
        for (let city in shortestTimes) {
            if (!visited.has(city) && (current === null || shortestTimes[city] < shortestTimes[current])) {
                current = city;
            }
        }

        if (current === null || shortestTimes[current] === Infinity) break;

        // الحي الحالي تم تثبيته ولن يتغير وقت وصوله
        visited.add(current);

        // خطوة الاسترخاء (Relaxation): فحص جيران هذا الحي
        for (let neighbor in map[current]) {
            if (visited.has(neighbor)) continue;

            const tripTime = map[current][neighbor];
            const newTotalTime = shortestTimes[current] + tripTime;

            // إذا وجدنا طريقاً أسرع مما كنا نعرف، نقوم بتحديث الدفتر فوراً
            if (newTotalTime < shortestTimes[neighbor]) {
                shortestTimes[neighbor] = newTotalTime;
                cameFrom[neighbor] = current; // نسجل: "وصلنا للجار عبر هذا الحي"
            }
        }
    }

    return { shortestTimes, cameFrom };
}

// دالة رسم خط السير بالأسهم:
function showRoute(cameFrom, destination) {
    const route = [];
    let step = destination;
    while (step) {
        route.unshift(step);
        step = cameFrom[step];
    }
    return route.join(" ➔ ");
}

const result = dijkstra(cityMap, "A");
console.log(result.shortestTimes); // { A: 0, B: 4, C: 2, D: 5 }
console.log(showRoute(result.cameFrom, "D")); // A ➔ C ➔ D

5. لغز الأوزان السالبة: لماذا تغلق الخوارزمية عينيها عنها؟

ماذا لو كان هناك شارع فيه (وزن سالب)؟ في الواقع، الوزن السالب يشبه "كوبون خصم" أو "كاش باك" يقلل التكلفة الإجمالية كلما مررت به.

لماذا تنخدع ديكسترا؟

تذكر أن ديكسترا خوارزمية جشعة مستعجلة، مبدأها الأساسي: "المدينة التي انتهيت منها وقررت أنها الأقصر، أضع عليها ختم (تمت الزيارة) ومستحيل أن أعود لأفكر فيها مرة ثانية".

تخيل هذا الموقف:

  • طريق مباشر من A إلى B يكلفك 3 جنيهات. تختاره ديكسترا وتغلق ملف B للأبد.
  • طريق آخر طويل من A إلى C يكلفك 10 جنيهات.
  • لكن هناك كوبري من C إلى B يعطيك كاش باك -9 جنيهات! يعني لو ذهبت عبر C، ستصبح التكلفة الإجمالية للوصول إلى B: \(10 - 9 = 1\) جنيه فقط (أرخص بكثير من 3)!

ديكسترا لن تكتشف ذلك أبداً لأنها أغلقت ملف B مبكراً وافترضت بسذاجة أن التكاليف في الدنيا كلها تزيد ولا تنقص. لذلك في الشوارع التي تحتوي على أوزان سالبة، لا نستخدم ديكسترا أبداً، بل نستخدم خوارزمية أخرى اسمها Bellman-Ford.
