الدرس التالي: خوارزمية بيلمان-فورد (Bellman-Ford)

البطل الحقيقي عند وجود العروض والخصومات (الأوزان السالبة) وكاشف فخاخ الديون اللانهائية!

1. التمهيد من الدرس السابق: لماذا احتجنا بديلاً لديكسترا؟

في الدرس السابق اكتشفنا نقطة ضعف خطيرة: ديكسترا خوارزمية "طماعة ومستعجلة"، تغلق المدينة فور وصولها إليها وتفترض أن التكاليف مستحيل أن تقل لاحقاً.

قصة من الواقع (كوبونات الخصم)

تخيل أنك تشتري من متجر إلكتروني:

  • اخترت خدمة توصيل عادية وسريعة كلفتك 40 جنيهاً (ديكسترا ستعتمدها فوراً وتغلق الطلب).
  • لكن هناك خيار آخر: لو اشتركت في الباقة الذهبية أولاً بـ 50 جنيهاً، المتجر يعطيك كوبون كاش باك بقيمة (-30 جنيهاً) عند شحن المنتج!
  • التكلفة الإجمالية في المسار الثاني أصبحت: \(50 - 30 = 20\) جنيهاً فقط!

ديكسترا لن تكتشف هذا التوفير أبداً، وهنا يأتي دور خوارزمية Bellman-Ford الصبورة والمتأنية التي لا تتعجل في اتخاذ القرار.

2. كيف تفكر الخوارزمية؟ سر قاعدة (V - 1) جولات

بيلمان-فورد لا تستخدم مبدأ الطمع، بل تستخدم أسلوباً مضموناً اسمه التكرار المنظم (Relaxation Iterations):

قاعدة المترو والمحطات

لو عندك خط مترو فيه 4 محطات (A ← B ← C ← D):

  • لكي تسافر من المحطة الأولى إلى الأخيرة، أقصى عدد من التبديلات (الوصلات) الممكنة بدون لف في دوائر هو: 3 وصلات فقط (عدد المحطات ناقص 1).
  • لذلك تقول لك الخوارزمية: "سأمر على كل شوارع الخريطة بلا استثناء وأقوم بتحسينها، وسأكرر هذا المرور الشامل عدد مرات يساوي (عدد العقد - 1)".
  • إذا كان لديك 4 عقد، سنقوم بـ 3 جولات فحص كاملة لنضمن وصول تأثير أي تحديث إلى آخر الخريطة.

4. الميزة الخارقة: كشف فخاخ الديون اللانهائية (Negative Weight Cycles)

هناك مصيبة قد تحدث في الرسوم البيانية، لا يمكن لأي خوارزمية حلها لأنها تمثل ثغرة لانهائية:

ما هي الدورة السالبة (Negative Cycle)؟

تخيل بنكاً يمنحك عرضاً غريباً: إذا حولت فلوسك من البنك (1) إلى البنك (2) ثم أرجعتها، تكسب ربحاً إضافياً! فتقوم بالدوران حول هذين البنكين آلاف المرات لتجمع أرباحاً لا نهائية.

في الرسوم البيانية، إذا كانت هناك حلقة دوران مجموع أوزانها سالب، فإنك كلما درت فيها تنخفض المسافة إلى سالب مالانهاية \((-∞)\)!

كيف تكتشفها بيلمان-فورد؟

بعد إنهاء الـ \((V - 1)\) جولات الرسمية، تقوم الخوارزمية بـ جولة إضافية واحدة أخيرة: إذا وجدت أن أي مسافة لا تزال تنخفض، تصرخ الخوارزمية وتطلق تحذيراً: "يوجد فخ دورة سالبة في الخريطة، المسار الأقصر غير معرف!".

5. تطبيق الخوارزمية بلغة JavaScript مع كشف الدورات السالبة

لاحظ كيف نتعامل هنا مع قائمة بسيطة من الحواف (Edges Array) بدل المصفوفات المعقدة:

// تعريف الحواف: من أين، إلى أين، وما هو الوزن
const edges = [
    { from: 'A', to: 'B', weight: 4 },
    { from: 'A', to: 'C', weight: 5 },
    { from: 'B', to: 'C', weight: -2 }, // وزن سالب (خصم)
    { from: 'C', to: 'D', weight: 3 }
];

const nodes = ['A', 'B', 'C', 'D'];

function bellmanFord(nodes, edges, startNode) {
    const distances = {};
    const previous = {};

    // 1. التهيئة: البداية 0 والباقي Infinity
    nodes.forEach(node => {
        distances[node] = Infinity;
        previous[node] = null;
    });
    distances[startNode] = 0;

    // 2. تكرار الفحص الشامل (عدد العقد - 1) مرات
    for (let i = 1; i <= nodes.length - 1; i++) {
        edges.forEach(({ from, to, weight }) => {
            if (distances[from] !== Infinity && distances[from] + weight < distances[to]) {
                distances[to] = distances[from] + weight;
                previous[to] = from;
            }
        });
    }

    // 3. الجولة الإضافية لكشف الدورات السالبة (Negative Cycle Check)
    for (let { from, to, weight } of edges) {
        if (distances[from] !== Infinity && distances[from] + weight < distances[to]) {
            throw new Error("تحذير: تم اكتشاف دورة سالبة! أقصر مسار غير نهائي.");
        }
    }

    return { distances, previous };
}

const result = bellmanFord(nodes, edges, 'A');
console.log(result.distances); // { A: 0, B: 4, C: 2, D: 5 }

6. جدول الملخص: متى تختار ديكسترا ومتى تختار بيلمان-فورد؟

وجه المقارنة ديكسترا (Dijkstra) بيلمان-فورد (Bellman-Ford)
فلسفة العمل جشعة وسريعة (Greedy) شاملة ومتأنية (Dynamic Programming / Relaxation)
الأوزان السالبة تفشل تماماً وتضلل النتائج تتعامل معها بكفاءة وتصل لأفضل حل
كشف الدورات السالبة لا تستطيع تكشفها فوراً بالجولة الإضافية
السرعة والتعقيد سريعة جداً: \(O((V + E) \log V)\) أبطأ نسبياً: \(O(V \times E)\)
القرار الهندسي استخدمها دائماً إلا لو وُجدت أوزان سالبة استخدمها في الأنظمة المالية والشبكات ذات الخصومات
